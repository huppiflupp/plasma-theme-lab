# External review of CDE Copper (09.10.2026)

The review as written, followed by the work status. The reviewer's priorities:
first remove the home-network defaults, then right-click on task buttons and
drag and drop onto tiles. In addition (user request): split up main.qml.

## Overall impression

The feature set is unusually large for a theme project. The project has long
since stopped being a theme and is its own desktop shell on top of Plasma:
console with subpanels, pager, layout store, style manager, lock screen shell,
GTK theme, Plymouth, GRUB, login greeter. The look is consistent and
coherent, the Dolphin dialogs look convincingly like Motif. The weaknesses
lie less in what is missing than in focus, usability of the settings and
readiness for other users.

## What is missing

- **Window management on the task buttons.** No right-click menu on windows
  in the bar: close, minimise, move to another workspace, "keep above" are
  missing. Plasma's task manager can do this; here you have to go to the
  decoration's window menu.
- **Everyday laptop use.** No battery status, no Bluetooth, no keyboard layout,
  no brightness in the console. Everything only behind the hidden tray button,
  because every tray icon is hidden by default. On a notebook the battery is
  two clicks away.
- **Drag and drop.** No DropArea in the console: you cannot drag a file onto the
  editor tile, reorder launchers by dragging, or drag a program from the menu
  into a tile. CDE could drop files onto panel controls; a core feature of the
  original.
- **Notifications.** Only styled through Plasma's surfaces, no own presentation,
  no history in the console (README: "not achieved").
- **X11 untested**, although the target audience tends to use X11. At least a
  smoke test.
- **Multiple physical screens** not validated according to TESTING.md, although
  "one console per screen" is advertised.
- **Keyboard operation** only partial: subpanels yes, application menu and
  auto-hide unverified. Never tried with a screen reader.

## Usability and improvements

- **Settings overloaded.** ~35 keys on five pages, texts like
  "Floating, a gap from the screen edge (off: on the edge)" – parenthetical
  double explanations show that the option is not self-explanatory. The
  "Front Console" page mixes edge, visibility, tray, contrast, LLM hosts.
  Organise by user questions: where is the console, what does it show, what
  does it look like.
- **Window display: three switches for one decision** (windowDisplay,
  workspaceWindows, showWorkspaces). Better one choice with five variants.
- **Launcher page** good, but reordering only via arrow buttons; the README
  screenshot still shows "Help" instead of "Layouts".
- **Style manager** as a page in the console settings; switching palette,
  applying, restarting programs is a break compared with dtstyle. A hint
  about which programs still look old.
- **Workspace buttons** are called "1", "2 Two", "3 Three": either all numbers
  or all names.
- **Popups under Wayland** open at the full size of both menu levels with a
  transparent remainder; the invisible part catches clicks. Check deliberately.

## Maturity and technical debt

- **Home-network names in the product.** The LLM host default contains 245k, ai395, x9,
  victus; the help text says "ai395:8090 is blocked". Default empty, text
  generic. The most urgent single item.
- **main.qml has 2135 lines** (clock, pager, network, volume, LLM, tray,
  layouts). Keeper, slot and popups into their own files.
- **QML warnings from the config pages** at startup; the cfg_*Default pattern
  has to be kept up with every option on all pages.
- **Versions grow faster than testing.** 14 releases on 7/8 Oct;
  TESTING.md is 54 KB of prose. A short checklist per release.
- **Long dependency list** (Kvantum, PyGObject, Spectacle, kdialog, nmcli,
  wpctl, gtk-launch, P5Support); the user only sees after installation
  which tiles stay empty.
- **Translation German only**; German texts in no screenshot.
